# AI-секретарь госоргана

> Репозиторий команды **Krias-rep3** · репетиция хакатона BAITC

Агент принимает обращение гражданина, классифицирует его, находит основания
в регламенте и готовит черновик ответа на русском и казахском языках.
Каждый шаг агента пишется в JSON-трассировку.

## Что делает

1. **Классификация обращения** — `справка` / `жалоба` / `запись`.
2. **Поиск оснований** — из регламента (`data/reglament.md`) достаются
   3 наиболее релевантных пункта с указанием номера.
3. **Черновик ответа** — двуязычный (ru / kk), со ссылками на найденные пункты.
   Для типа `запись` — с фактическими датой, временем и талоном.
4. **Трассировка** — все шаги, вызовы инструментов и их результаты
   сохраняются в `logs/agent_log.json`.

## Архитектура: детерминированный pipeline

Шаги выполняются в фиксированном порядке, определяемом оркестратором.
Модель не выбирает инструменты — они вызываются жёсткой веткой по типу
обращения. Это сознательный выбор для репетиции: ветвление по ответу модели
добавляет обработку отказов (модель не вызвала, вызвала не тот, мусор в
аргументах), которую на слабой локальной модели всё равно приходится
страховать теми же проверками. Агентность подтверждается многошаговостью
и трассировкой, а не тем, кто выбрал инструмент.

```
обращение
   │
   ▼
[classify]  ──► Classification (тип + уверенность)
   │
   ▼
[retrieve]  ──► 3 пункта регламента (косинусная близость)
   │
   ├─ если тип = "запись" ──► [book_appointment]  ──► Appointment (талон, дата, время)
   │
   ▼
[draft_ru]  ──► текст на русском, со ссылками на пункты
   │
   ▼
[translate_kk] ──► тот же текст на казахском (перевод, не генерация)
   │
   ▼
AgentResult + logs/agent_log.json
```

## Стек

| Слой | Технология |
|------|-----------|
| Язык | Python 3.11 / 3.12 |
| LLM | OpenAI-совместимый API (провайдер переключается конфигом) |
| Поиск | BGE-m3 (`sentence-transformers`) или лексический (по `EMBED_BACKEND`) |
| API | FastAPI, порт 8100 |
| Тесты | pytest |

```
│   ├── tools.py        инструменты (фиктивный календарь)

```

## Запуск

```bash
# Создание виртуального окружения
python3.11 -m venv .venv   # или python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# Конфигурация
cp .env.example .env        # указать LLM_BASE_URL, LLM_API_KEY, LLM_MODEL

# Одно обращение
python main.py --text "Прошу выдать справку о составе семьи"
python main.py --text "..." --json

# Пакетный прогон
python main.py --batch data/samples.json

# API
uvicorn api:app --host 0.0.0.0 --port 8100
# POST /appeal  {"text": "..."}
# GET  /health
```

## Поиск и EMBED_BACKEND

По умолчанию используется BGE-m3 (`sentence-transformers`). Если веса или
GPU недоступны (демо, чужая машина), переключитесь на лексический поиск:

```bash
export EMBED_BACKEND=lexical
```

Возможные значения: `bge-m3` (по умолчанию), `lexical`. При недоступности
BGE-m3 происходит автоматический fallback с логированием предупреждения.

## Календарь

Фиктивный: 3 отделения, слоты по 30 минут с 09:00 до 17:00, обед 13:00–14:00,
выходные пропускаются. Ближайший свободный слот — не раньше следующего
рабочего дня. Талон вида `A-042`, детерминированный от услуги и даты.

## Тесты

```bash
/private/tmp/hakaton-codex-py312/bin/python -m pytest -q -p no:cacheprovider tests/
```

Тесты не требуют сети и реальной модели: LLM подменяется через `FakeLLM`,
эмбеддер — через `FakeEmbedder`. Тесты на свои модули лежат в
`tests/test_<модуль>.py`.

## Лог

Один файл `logs/agent_log.json` — трассировка последнего запуска (известное
ограничение репетиции: параллельные обращения через API пишут в один файл).

## Контракт типов

Все структуры данных — `Appointment`, `Clause`, `Classification`, `Draft`,
`AgentResult` и протоколы — объявлены в `agent/types.py`. Это единственный
источник истины, файл заморожен.

## Необходимые учётные данные

Для работы нужен OpenAI-совместимый LLM-провайдер. Минимум в `.env`:

```
LLM_BASE_URL=https://your-provider.example.com/v1
LLM_API_KEY=your-api-key
LLM_MODEL=qwen3-35b   # или любая модель провайдера
```

## Состояние и что проверено

Прототип собран двумя агентами параллельно по `SPEC.md`: логика решений
(регламент, поиск, классификация, черновик, оркестратор) и обвязка
(клиент модели, трассировка, инструменты, CLI, API, тесты).

Проверено офлайн, без обращения к модели:

- 64 теста логики решений (регламент, поиск, классификация, черновик,
  оркестратор) — зелёные;
- сквозной прогон `python scripts/demo_offline.py`: заявка «записаться
  на приём 24 сентября за справкой» даёт тип `запись`, пункты 3.2/3.1/3.4,
  извлечённую дату `2026-09-24`, бронирование настоящим инструментом и
  ссылки `п. 3.2`, `п. 3.3` в обеих языковых версиях;
- `logs/agent_log.json` в репозитории — результат этого офлайн-прогона
  (модель помечена как `offline-demo`); реальный запуск перезапишет его.

Не проверено и требует ключа к модели:

- качество формулировок черновика на русском и казахском;
- сохранение номеров пунктов и сроков при переводе на казахский —
  самое вероятное место, где понадобится правка промпта;
- `pytest` целиком: тесты обвязки (`test_llm`, `test_api`, `test_tools`,
  `test_trace`, `test_main`) требуют установленных зависимостей.
